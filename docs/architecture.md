# 精简首版架构

Personal Radar 是一个单体 Next.js 应用：页面与 API 在同一进程中，SQLite 数据位于 `.data/database.sqlite`。Chrome/Edge 扩展只在用户主动点击时把当前页面发送到 `127.0.0.1:3210`。

前端在同一首页内使用左侧模块栏切换“雷达工作台”和“自由浏览”。雷达工作台承载关注对象、情报采集、日报、画像和备份；自由浏览的任意关键词入口只生成必应/百度公开搜索链接并在新标签页打开，关注对象入口则调用独立 API，让现有 CCSwitch Claude 联网检索、阅读并在当前页整理带来源链接的新内容。模块选择与 AI 整理结果仅保存在浏览器当前状态，结果不会自动写入数据库。

关注对象调研只由用户点击触发，不使用后台 worker 或任务队列。服务优先请求 Claude Web Search，并把关注对象的网站来源作为允许域名；供应商未返回可核对来源时，回退为本地公开搜索与 SSRF 安全正文读取，再交给同一 CCSwitch Claude 整理。搜索结果在读取前和重定向后都会校验允许域名，站外结果会被丢弃；供应商拒绝、超时、无来源或指定网站无结果时均返回真实错误，不生成替代事实。

首版不使用独立 worker、通用队列、monorepo、字段级加密、插件框架或运行时多 Agent。耗时功能按具体用例实现，并向用户显示进度和错误。

当前已完成关注对象、关键词、信息源、公开 URL 正文提取、扩展主动采集、AI 摘要、确认收录、今日情报、简单画像建议及 ZIP 导入导出。网站登录状态按精确 `origin`（协议、主机名和非默认端口）归一化，由扩展在用户主动点击时回传；本地 Web 服务不读取浏览器 Cookie。

扩展仍只有 `activeTab`、`scripting` 与 `http://127.0.0.1:3210/*` 本地主机权限。它仅在用户点击“收录到 Personal Radar”后执行一次脚本，从当前标签页提取标题、完整页面 URL、用户选文和清理后的可见正文；表单、输入控件、隐藏节点、登录/密码、私信和支付相关容器先在页面内剔除。正文最多 30,000 字，选文最多 4,000 字，本地 API 使用严格 Zod 白名单再次校验。

可选的 Personal Radar Research Skill 独立于应用运行时。它在用户明确调用后，使用 Codex 托管浏览器执行一次“精品渠道、主流定调、随机小众挖掘”只读流程，并在报告后停止。公开仓库中的精品渠道清单为空白模板，不包含真实关注对象或链接。Skill 不创建后台任务、队列或常驻 Agent；内容收录和渠道提升仍必须由用户再次确认，并通过现有本地接口完成。

扩展采集结果直接写入 `saved_items`，Web 页面在重新获得焦点时刷新列表。用户可以随后调用现有 CCSwitch/Claude 配置生成摘要，修改并确认后再写回该采集记录。

今日情报以 `APP_TIMEZONE`（默认 `Asia/Shanghai`）计算业务日期。候选内容只来自同一关注对象在所选业务日期内的 `saved_items`；用户最多勾选 12 条后调用现有 AI 配置生成可编辑草稿。只有用户确认后才写入 `daily_reports` 和 `daily_report_items`，同一关注对象同一天重复确认会更新原日报及条目关系。服务不后台抓取、不模拟登录，也不会在没有候选内容时生成情报。

简单画像只使用已经确认进入 `daily_report_items` 的采集内容作为证据。AI 可以提出当前关注主题、具有时间证据的近期变化、内容呈现出的学习或工作方向，以及推荐检索关键词。生成结果只保留在当前页面内；用户逐条确认时才写入 `profile_suggestions`。服务端再次过滤性格、生活状态、健康、政治、宗教、性取向等敏感属性，并按类型和值去重。未确认建议不会进入数据库。

备份导出使用 SQLite 在线备份 API 生成一致性数据库快照，再与 `.data/library/` 和非敏感 `config.json` 一起写入 ZIP；不会直接复制 WAL，也不会读取 `.env.local`、CCSwitch 配置、Cookie 或密钥。导入仅允许固定路径，限制 ZIP 大小、条目数量、单文件和解压总量，并在替换前执行配置版本、SQLite `integrity_check`、必需表和外键检查。当前数据库和资料库先保存到 `.data/import-safety/`，替换失败时自动恢复；成功后安全副本继续保留。

Windows 生产安装入口为 `setup-windows.cmd`：脚本校验 Node.js 24、npm 11+ 和锁文件，使用 `npm ci` 安装依赖，随后执行数据库 migration 与生产构建。`start-personal-radar.cmd` 会检查依赖和构建产物，在每次启动前应用幂等 migration，再调用 `next start --hostname 127.0.0.1 --port 3210`。开发命令同样显式绑定该地址，不依赖可被外部环境覆盖的默认监听值。

公开仓库只保留空白 `.env.example`，不包含真实 AI 服务地址、令牌或私人数据。`.gitignore` 覆盖 `.data/`、所有本机环境文件、SQLite 旁文件、ZIP 备份、日志、导入安全副本、扩展本地状态、`.npmrc` 和常见密钥文件。`scripts/check-public-repo.mjs` 使用 Git 的公开候选文件集合复核忽略规则、敏感路径、常见密钥特征、示例配置、扩展权限与 npm 监听命令；它既可在本机运行，也属于 CI 必经步骤。

GitHub Actions 在 `windows-latest` 和 Node.js 24 上运行，权限仅为读取仓库内容，不持久化 checkout 凭据，不读取仓库 Secrets。AI 环境变量保持空白，数据库写入 runner 临时目录，测试数据全部使用 `example.com`、保留测试地址和明确标注的虚构文本。CI 依次执行 `npm ci`、公开仓库安全检查、生产依赖审计、数据库 migration、测试、类型检查与生产构建。

至此 V1-01 至 V1-07 的精简首版闭环全部完成，并在相同安全边界内增加 V1-08 用户主动触发的三段式调研 Skill；后续功能仍应遵守冻结规格，不引入对外监听、扩展权限扩张、后台模拟登录、通用任务队列或运行时多 Agent。
